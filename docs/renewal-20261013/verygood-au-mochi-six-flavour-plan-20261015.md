### 1.1 6가지 맛과 가격 (AUD)

| stable flavour ID (제안) | 한국어 | 영문 화면명 (제안) | 판매가 | 서버 cents |
|---|---|---|---:|---:|

`Butter & Red Bean`, `Nama Chocolate`는 화면용 영문 이름 제안이다. 제조·알레르기·보관 문구는 실제 원료 정보가 제공되기 전까지 추측하지 않는다.

- **기존 고정 시그니처 4구 $35 미배포 로컬 규칙 제거.** 현재의 `signature / custom-four / quantity` 모찌 주문 UI는 새 흐름으로 대체한다.
- **4구 선물세트 가격은 선택한 4개 단품 가격의 합계.** 세트 가격 할인 없음. **4구 선물박스 가격 $0.**
- 4개에는 중복 맛을 허용한다. 예: 생초콜릿 4개=$32, 딸기 4개=$40.
- **동일 구성 박스는 박스 수량 조정**(`x 1`, `x 2`, ...)으로 판매. 한 박스당 실물 4개.
- **다른 구성 박스는 별도로 생성**하고 장바구니에서 독립된 묶음으로 보여준다.
- **단품 판매는 모든 6종에서 수량 1개 이상 자유 선택.** 기존 단품 개별포장 옵션 **선택 시 개당 $0.50** 유지. 모찌에는 컵케이크 $100 포장비 면제 적용하지 않음.
- 단품으로 4개 또는 4의 배수(8, 12...)를 담았다면 **무료 4구 박스 구성 전환을 제안**하되, 고객 동의 없이 자동 전환·임의 배분하지 않는다. 각 박스에 들어갈 맛 구성을 명시적으로 결정해야 한다.
- 선물박스에는 개별포장 $0.50를 자동 중복 부과하지 않는다. 박스·리본의 실제 구성은 승인된 실물 포장 기준으로만 설명.
- 신규 모찌 카드 수는 늘리지 않는다. Chocolate 목록에는 **Chocolate Mochi 카드 1개**. 상세 주소 `/chocolates/chocolate-mochi` 유지.
- 모찌에 구형 `Signature 4 $35`, 정해진 4종 기본 구성, 자동 시그니처 전환을 노출하지 않는다. 실제 운영 케이크·초콜릿 주문/스냅샷/독립 과거 reader는 보존한다.

## 2. 제안하는 최종 상세 UX

### 2.1 시작 화면

```
Chocolate Mochi
Choose from 6 flavours · From AUD $8.00

[🎁 나만의 4구 선물세트]    [🍫 단품 구매]
    Gift box included FREE         원하는 만큼 자유 선택
```

기본 활성 탭은 **4구 선물세트**. 단품 탭은 즉시 전환 가능. 큰 주문 방식 선택은 `select`보다 두 개의 카드형 탭/버튼을 우선. 모바일 390px에서 44px 이상 터치 영역.

### 2.2 선물세트 만들기

1. 6맛 각각 `[−] [수량] [+]` 컨트롤과 단가 표시.
2. 진행도 `0 / 4개 선택` → `4 / 4개 완성`. **정확히 4개일 때만 [이 구성으로 담기] 활성화**.
3. 구성 단가 = 선택 4개의 개별 단가 합계. `선물박스 FREE`는 금액 0 표시. 4개보다 적거나 5개 이상 담을 수 없게 입력 단계에서 제한.
4. 동일 박스 수 `[−] 1 [+]`; 최종 금액 = `구성 단가 × 박스 수`.
5. 완성 후 `[이 구성으로 담기]`. 담긴 뒤 화면에는 `[같은 구성 수량 늘리기]` / `[다른 구성 만들기]` / `[장바구니 보기]`를 제시.
6. `[다른 구성 만들기]`는 현재 저장한 박스를 보존하고 6개 카운터만 0으로 초기화한다. 다른 조합은 별도 박스 그룹/라인으로 담는다.
7. 이미 장바구니에 같은 맛·동일 포장 구성의 박스가 있으면 수량 합산 가능. **맛 조합이 다르면 자동으로 합치지 않는다.**
8. 장바구니에서 각 박스 구성과 박스 수 수정/삭제 가능. 상품명만 보여주고 내부 구성은 숨기지 않는다.

### 2.3 단품 구매

1. 같은 6종 목록에서 각 맛을 0개 이상 선택. 모든 수량 합계가 1개 이상이어야 추가 가능.
2. 기본은 기존 단품 포장 방식. 추가 옵션: `각각 개별포장 (+$0.50/개)`.
3. 선택한 단품에만 개별포장 수수료 `선택 수량 × 50 cents` 부과. 포장을 선택하지 않은 다른 라인은 가산하지 않는다.
4. 단품 4개 이상을 선택했을 때 `4구 선물박스로 무료 포장할 수 있어요` 안내. **전환 버튼은 이용자 의사를 확인**하며, 선택 가능한 4개씩 박스 구성으로 나누는 화면을 열어야 한다.
5. 예: 단품 5개 → 사용자가 원하는 4개를 박스 A로 지정하고 1개는 단품으로 유지 가능. 8개 → 명시적으로 박스 A/B 각각 4개를 배정. **4의 배수라는 이유로 자동 포장하지 않는다.**
6. 전환을 취소하면 단품 상태 유지. 전환을 확정하면 원래 단품 수량에서 박스에 배정한 개수만 제거하여 **실물 중복 계산/이중 청구 금지**.
7. 개별포장을 선택한 단품을 무료 선물박스로 전환하면 해당 4개에 대한 개별포장비가 남지 않도록 고객에게 요금 변화를 확인시킨다.

### 2.4 장바구니·관리자·생산 화면 예시

```
Gift Box A   딸기1 · 청포도1 · 바나나1 · 생초콜릿1
             $37.00 / box × 2 = $74.00
             2 boxes / 8 pieces / gift packaging $0

Gift Box B   귤2 · 앙버터2
             $35.00 / box × 1 = $35.00
             1 box / 4 pieces / gift packaging $0

Singles      생초콜릿3 / individually packaged
             $24.00 + packaging $1.50 = $25.50

TOTAL $134.50 · 3 gift boxes + 3 singles · 15 pieces
```

운영자용 주문·PIN·Packing/Production·CSV·Notification·Reminder는 **박스 A/B별 정확한 조합과 실제 맛별 총수량**을 보존한다. 각 선물세트 행은 안정적 lineId가 있으며 같은 상품 카드 아래의 다른 구성과 혼동되지 않는다.

- 모찌 가격/이름은 4개 순서 기반 `MOCHI_PRICES`, `MOCHI_NAMES` 배열.

### 3.1 최신 계약 결정 — 사용자 지시로 대체

- 사용자가 모찌의 Production 미배포를 다시 확인했다. **기존 Renewal v2를 유지**하며 모찌만6종으로 바꾼다. v3와 미배포35달러 보존 요구는 폐기한다.
- 저장 컨테이너 version2와 policyVersion v2 유지. 기존 케이크·초콜릿과 역사적 reader는 수정하지 않는다.
- 6개의 고정 flavour ID를 사용하고 가격·포장비·박스수는 서버가 계산한다.
- 이전4종 모찌 카트는 변환하지 않고 별도 보관·재선택 안내한다. 다른 상품 카트는 유지한다.
- 읽기 전용 확인: 로컬 기록상 운영배포 없음,운영 공개 llms.txt에 모찌/Renewal 표기 없음. 환경에 운영 Appwrite 조회 자격증명이 없어 DB건수 직접 검증은 하지 못했다. 사용자 미배포 확인을 구현 기준으로 삼으며 운영데이터는 변경하지 않는다.

구현된 신규 주문 입력 형태:

```json
{"offerId":"mochi","mode":"gift-four","flavourCounts":{"strawberry":1,"green_grape":1,"mandarin":0,"banana":1,"butter_redbean":0,"nama_chocolate":1},"quantity":2,"individualPackaging":false}
```

```json
{"offerId":"mochi","mode":"singles","flavourCounts":{"strawberry":0,"green_grape":0,"mandarin":0,"banana":0,"butter_redbean":0,"nama_chocolate":3},"quantity":1,"individualPackaging":true}
```

각 라인에는 기존처럼 별도의 `lineId` 부여; 위 JSON은 개념 설명이며 실제 타입/필드 이름은 기존 저장 호환성을 확인하여 최소 확장. `gift-four`의 단일 박스 구성을 `quantity`만큼 반복해 저장. `singles`의 실물 개수는 `sum(flavourCounts)`이며 `quantity`는 1로 고정하여 이중 곱셈 방지. UI에서 포장된 단품과 비포장 단품을 섞어 담으면 포장 상태별 서로 다른 라인에 저장.

### 3.2 서버 불변식

- 6개 flavor ID 모두 식별 가능하고 허용 ID 이외 거부. 맛별 수량은 안전한 비음수 정수.
- 선물박스 `sum(flavourCounts) === 4`, 박스수 ≥1인 안전한 정수. 박스수 2이면 실물 8, 포장 2상자, 맛별 totals = counts×2.
- 단품 `sum(flavourCounts) ≥1`, 상자수 0, 실물 합계로 가격 계산.
- 판매가는 정수 cents 계산. 선물박스 포장비 0, 단품 개별포장 단가50c·수량 검증. 쿠폰/할인 기존 정책 별도 유지.
- 고객 payload의 `price`, `total`, `giftBoxCount`, `packagingFee` 등의 금액 필드를 신뢰하거나 그대로 저장하지 않는다.
- 같은 구성의 여러 박스는 카트 identity가 같을 경우 병합 가능. 서로 다른 구성, 모드, 포장상태는 병합하지 않음.
- 저장된 snapshot은 주문 시점의 이름, 정책 버전, 단가, 박스별 맛 구성, 수량, 총 실물 수, 총 박스 수, 포장 상태, 총액을 포함.
- 고객이 앞서 저장한 v1/v2 장바구니를 열면 새 가격으로 몰래 변환하지 않는다. **기존 장바구니는 명확한 안내 + 재선택** 한다.
- 모찌 신규 접수 플래그는 현재 기본 닫힘 유지. 다른 상품/Custom Cake/KR/과거 쿠폰/픽업/알림에는 영향 주지 않음.
