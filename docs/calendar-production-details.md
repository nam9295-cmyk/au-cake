# PIN Calendar Production Details

The existing PIN login and signed `calendar:read` token (30-day TTL) remain unchanged. Per the approved production policy, valid PIN tokens now authorize Custom Cake production fields only. No Appwrite administrator, email/password login, public storage link or expanded database document permission is required.

Monthly `calendar-events` still returns schedules only. Custom Cake labels include flavour parsed from an exact anchored `[Flavour: ...]` prefix; a compact `customCake:{tier,size,quantity,flavour}` projection lets small calendar cells display flavour separately. No design/additional request text is included in the month response. Missing flavour is null; the UI shows Not specified. A prefix must be a complete first line (or the whole note), with 1–64 non-newline characters and no surrounding whitespace; malformed prefixes remain design text.

`calendar-production-detail` takes exactly `{token,eventId:'custom-cake:<requestNumber>'}`. Token authentication precedes all snapshot reads. It reads at most two rows by lookupKey and rejects missing/duplicate/unrelated identities. Response is exactly `{id,pickupDate,pickupTime,status,lines:[{tier,size,quantity,flavour,designRequest,figurineSource}],additionalRequest}`. Each Custom Cake line is projected; S’more rows, customer identity, phone/email, photoRef/storage IDs, quote/history/audit and admin metadata are absent. Additional Request comes exclusively from immutable `snapshot.request.requestNote`; it is not inferred from lookupResponse. All calendar action responses use no-store.

Design and additional requests are approved free text: React text nodes with preserved line breaks, never HTML. Figurine labels are No Figurine / Customer Provided / Shop Sourced without changing saved enums. Detail loads on selection only; logout, date/month changes, refresh, unmount and newer selections invalidate in-flight detail responses.

No columns, flavour backfills, schema migration or historical order edits. Existing privacy tests remain and distinguish month omissions from detail allowlist. Deploy from a clean artifact after comparing and preserving the server checkout's uncommitted calendar changes read-only. Rollback can remove the new detail UI/action while preserving PIN auth and the manual-quote-compatible readers from the separate discount checkpoint. Do not reset/pull/clean the existing server checkout or overwrite its files.
